# Performance & weight

## Measure first

```bash
pnpm run perf:bundle                      # android: bundle size, gzip, and a ranked table of packages
pnpm run perf:bundle -- --platform ios
pnpm run perf:bundle -- --update-budget   # record today's size (+5% headroom) in perf-budget.json
pnpm run perf:budget                      # fail if over budget (run weekly by maintenance.yml)
pnpm run dev:atlas                        # interactive module graph (Expo Atlas)
```

`perf:bundle` runs `expo export --source-maps --no-bytecode`, decodes the source map and credits every generated byte to the npm package (or `‹src/…›` folder) it came from. Sizes are of minified JS before Hermes bytecode — proportional to, not equal to, the bytes in the APK/IPA. The report is saved to `dist/bundle-report/report-<platform>.json`.

Native binary size is a different budget: build with `pnpm run build:local:android` and read the size it prints; every native module (camera, video, webview, Skia, …) adds to it whether or not a screen uses it.

## Measured (Expo SDK 58, release bundle)

| | Android | Android, tree-shaken | iOS |
|---|---|---|---|
| Bundle | 8,586 KB | **6,122 KB (−29%)** | 8,570 KB |
| Gzip (OTA download) | 1,859 KB | **1,435 KB (−23%)** | 1,855 KB |
| Modules | 5,746 | 3,359 | 5,736 |

Biggest owners before tree shaking: `lucide-react-native` 1.2 MB (the whole icon set — gone after tree shaking), `react-native-reanimated` 625 KB, `react-native` 595 KB, `src/components` 550 KB, `expo-router` 480 KB, `lucide` 408 KB (icon data used by `morphicons`, which reaches every icon, so it cannot be pruned), `reanimated-color-picker` 228 KB, `gifted-charts-core` 221 KB.

### Tree shaking

Expo's tree shaking is experimental in SDK 58 and turned on per profile with `EXPO_UNSTABLE_METRO_OPTIMIZE_GRAPH=1` + `EXPO_UNSTABLE_TREE_SHAKING=1` (`metro.config.js` adds `experimentalImportSupport` when they are set). It is enabled for the **`preview`** profile (EAS and `build:local:android`) so QA exercises it first; add the two variables to `production` once a preview build has been through the [QA checklist](MOBILE_QA_CHECKLIST.md). Measure locally: `EXPO_UNSTABLE_METRO_OPTIMIZE_GRAPH=1 EXPO_UNSTABLE_TREE_SHAKING=1 pnpm run perf:bundle`.

## Where this starter's weight is, and what to do about it

The curated list lives in [`script/lib/dependency-alternatives.ts`](../script/lib/dependency-alternatives.ts); `pnpm run deps:check` prints the entries for what is installed, and `perf:bundle` puts them next to the measured bytes. Summary:

| Package | Issue | Alternative | Native change | Effort |
|---|---|---|---|---|
| `react-native-calendars` | pulls in `moment`, `xdate`, `recyclerlistview` | `@marceloterreiro/flash-calendar`, or build on the Calendar UI + date-fns | no | M |
| `react-native-gifted-charts` | JS-thread animations; 17 chart types ship regardless | keep for light dashboards; `victory-native` (Skia, UI thread) for heavy ones — measure the Skia binary first | no | L |
| `axios` | second HTTP stack over `fetch` | ~60-line `fetch` wrapper (timeout, auth header, 401 refresh queue) | no | M |
| `@react-native-community/netinfo` | community module | `expo-network` `useNetworkState` | yes | S |
| `react-native-toast-message-ts` | older fork | `sonner-native` or `burnt` | no | S |
| `@react-native-community/datetimepicker` | platform-inconsistent UX | evaluate `@expo/ui` DateTimePicker | yes | M |
| `date-fns` | mostly formatting | `Intl.DateTimeFormat` / `RelativeTimeFormat` (Hermes) | no | S |
| `zod` 3 | largest schema lib | Zod 4 (`zod/mini`) or valibot | no | M |
| `@tanstack/react-query-devtools` | web-only, a runtime dependency | dynamic `import()` behind `isWeb && __DEV__` | no | S |
| `react-native-keyboard-controller` | installed, unused | adopt (`KeyboardProvider` + `KeyboardAwareScrollView`) or remove | yes | S |
| `babel-plugin-module-resolver` | blocks the SDK 58 Rust transformer | Metro tsconfig `paths`; drop custom Babel plugins, try `experiments.noxcturnalTransformWorker` | no | M |
| `reanimated-color-picker`, `number-flow-react-native` | demo-only | keep for demos; drop from apps built on the starter | no | S |

"Native change" means a `version` bump and a new dev build (`runtimeVersion` uses the `appVersion` policy).

## Runtime performance checklist

- **Lists** — `FlatList` with `getItemLayout`, `keyExtractor` and memoized rows; for long or complex lists evaluate `@legendapp/list` or FlashList.
- **Charts** — mount with `useChartReady(order)` (idle + stagger) and keep `animationDuration` short; never mount a whole chart gallery at once.
- **Images** — `expo-image` with `contentFit`, explicit sizes and `cachePolicy`; run `pnpm run images:optimize` after adding assets.
- **State** — Zustand per-field selectors; TanStack Query `staleTime` (5 min default) instead of refetch-on-focus everywhere.
- **Animations** — Reanimated worklets / CSS transitions on the UI thread; avoid JS-thread `Animated` loops.
- **Startup** — keep work out of the root layout; fonts and i18n load in parallel behind the splash screen (see `app/_layout.tsx`).
- **Storage** — `StorageService` reads hit an in-memory cache; don't store large blobs in SecureStore (~2 KB per value on some iOS versions).
- **Check on a real low-end Android device in a release build** (`build:local:install`) — dev builds are not representative. The pre-release sweep is in [MOBILE_QA_CHECKLIST.md](MOBILE_QA_CHECKLIST.md).
